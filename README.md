# Списки дел — Express и PostgreSQL

Автор: **Чирков Лев Сергеевич**, Moodle: **l1onesss**. Практическое задание от 24.10.2026. Проверка условий размещения: **14.11.2026**. Приложение: **https://express-final-l1onesss.onrender.com**. Размещено на бесплатном Render Web Service; данные хранятся в PostgreSQL Supabase.

Приложение позволяет создавать, переименовывать и удалять списки вместе с делами, добавлять дела, редактировать названия и менять статус выполнения. Удаление списка требует подтверждения. Интерфейс работает на HTML, CSS и JavaScript, адаптируется к телефону и поддерживает клавиатуру. Сайдбар переключает списки; уведомления исчезают автоматически. Токен хранится только в памяти страницы и исчезает после выхода или перезагрузки.

Выбран PostgreSQL в Supabase: есть постоянный бесплатный тариф и независимое подключение преподавателя к той же базе. Бесплатный план отличается от временного гранта отсутствием заранее установленного срока окончания, но ограничен квотами и приостанавливается после недели неактивности. Перед проверкой нужно убедиться, что проект активен. Timeweb требует оплаты ресурсов; на проверенном Helios нет Node.js/npm в стандартном пути. Платные ресурсы не создавались.

Сервер разделён на конфигурацию, HTTP-маршруты и PostgreSQL-репозиторий. Express проверяет Bearer-токен до разбора JSON, запросы параметризованы. `/api/session/` различает автора и преподавателя; `/api/author/` всегда возвращает автора работы, как требует PDF. Интерфейс преподавателя показывает его роль и отдельно ФИО с логином автора. Идентификатор, время и начальный статус дела задаются сервером через значения по умолчанию БД; ownerLogin берётся из конфигурации. Время возвращается строкой UTC ISO 8601.

Обязательный HTTP-контракт сохранён: POST дела принимает только title/runId, ответы дел содержат прежние шесть полей, GET списка требует runId. Отдельная таблица task_lists хранит названия и стабильный runId; переименование не меняет связь с делами. Триггер регистрирует список даже при независимой SQL-вставке дела с новым runId. Новый API возвращает названия, счётчики и дела выбранного списка. Интерфейс автоматически перечитывает БД каждые десять секунд и при возвращении на вкладку, сохраняя незавершённое редактирование.

Для запуска нужны Node.js 22+, зависимости из lock-файла и локальный `.env`. Проверенные версии: Node.js **22.17.0**, Express **5.3.0**, PostgreSQL **17.11**. `.env.example` не содержит секретов. Текущая база уже инициализирована. На новой базе `db:init` последовательно применяет schema.sql и lists.sql; пароли ролям назначаются отдельно по инструкции `docs/deployment.md`.

Роли `todo_app` и `todo_reviewer` имеют CRUD только учебных таблиц tasks/task_lists. RLS закрывает их для анонимных пользователей Supabase; преподавателю запрещены Auth, изменение схемы и TRUNCATE. TLS проверяет сертификат и имя сервера; публичный CA находится в `certs/`. Персональное дело «Итоговая работа 24.10.2026: l1onesss» сохранено в runId `manual`. Тесты проверяют контракт, роли, списки, браузерный CRUD и независимые изменения БД. Секреты находятся в игнорируемых `.env`/`.private/`; преподавателю отправляются только его реквизиты личным сообщением Moodle. В тему прикладываются HTTPS-адрес, README и точный commit либо ZIP без секретов.

## Сопоставление полей

| Поле JSON | Столбец public.tasks | Тип PostgreSQL / правило |
| --- | --- | --- |
| id | id | uuid, PRIMARY KEY, gen_random_uuid() |
| ownerLogin | owner_login | text, логин из конфигурации сервера |
| title | title | text, trim, 1–200 символов |
| done | done | boolean, по умолчанию false |
| runId | run_id | text, 1–64 символа A–Z/a–z/0–9/_/- |
| createdAt | created_at | timestamptz, now(); JSON UTC ISO 8601 |

## Команды

```powershell
npm.cmd ci
Copy-Item .env.example .env # Только при первом запуске; заполните .env
npm.cmd run db:init        # Только новая БД; нужна DATABASE_ADMIN_URL
npm.cmd start
# В другом терминале:
npm.cmd run seed
npm.cmd test
npm.cmd run test:integration
npm.cmd run test:browser   # Windows: установленный Edge; Linux: npx playwright install chromium
```

Открыть локально: `http://127.0.0.1:3000`. Публикация и независимое подключение: [docs/deployment.md](docs/deployment.md). Результаты проверки: [docs/verification.md](docs/verification.md).
